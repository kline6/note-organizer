C# + Modbus 工控上位机 全套零基础知识点总结

================================================================================
一、C# 基础常用关键字释义
================================================================================

class       ：定义类，相当于功能模板、图纸，比如 ModbusProtocol 就是一个功能类
public      ：公开权限，外部所有代码都能调用这个方法、变量
private     ：私有权限，只能在当前类内部使用，外部无法直接调用
readonly    ：只读修饰符，变量赋值之后永远不能修改，用来固定通信对象，防止手滑出错
new         ：创建实例，把模板变成实际能用的对象
void        ：方法执行完没有任何数据返回，只执行动作
ushort      ：无符号短整型，工控寄存器专用数据类型，存放位置、数值、地址
byte        ：字节类型，专门存设备地址、Modbus 指令报文
bool        ：布尔类型，只有 true（开启）、false（关闭）两个值，用于开关量控制
return      ：把方法内部运算好的结果，返回给外面调用处使用
构造函数    ：和类名同名的方法，创建对象时自动执行，用来传参数、初始化配置
变量        ：用来存放数据、存放对象的容器，只是名称，不是实际功能

================================================================================
二、两大核心对象详解
================================================================================

1. ModbusSerialClient
   身份：现成的第三方串口通信工具类（别人写好的"轮子"）
   作用：只负责两件事：打开串口、发送 Modbus 报文、接收设备回复数据
   创建格式：
       ModbusSerialClient 通信兵 = new ModbusSerialClient("COM3", 9600);
   参数说明：
       "COM3" ：电脑的串口号
       9600   ：通信波特率，设备和代码必须完全一致
   使用规则：只有new新建对象时，才能在后面加括号传配置参数；单纯声明变量不能加括号

2. _client
   身份：类内部定义的私有容器变量
   作用：专门用来存放外面传进来的ModbusSerialClient通信对象
   核心关系：
       ModbusSerialClient = 类型（是什么东西）
       _client            = 变量名（给这个东西起的内部名字）
   赋值方式：只能通过构造函数把外部通信对象传入赋值，不能直接写端口参数

3. ModbusProtocol
   身份：我们自己手写的 Modbus 功能工具类（"文书"）
   核心职责：
       不负责串口的打开 / 关闭
       只负责拼装标准 Modbus 指令、计算 CRC 校验
       调用传入的通信对象完成数据收发
   内部结构：
       私有容器：private readonly ModbusSerialClient _client; 存放通信对象
       构造函数：接收外部传进来的通信兵，完成绑定
       内置固定方法：读寄存器、写寄存器、读线圈、写线圈、读限位

================================================================================
三、对象绑定完整流程（核心串联逻辑）
================================================================================

1. 外部新建带端口、波特率的真实通信对象
   ModbusSerialClient 通信兵 = new ModbusSerialClient("COM3", 9600);

2. 新建我们自己的功能类ModbusProtocol，把通信兵传进去
   ModbusProtocol 文书 = new ModbusProtocol(通信兵);

3. 类内部构造函数完成赋值绑定
   public ModbusProtocol(ModbusSerialClient client)
   {
       _client = client;
   }

绑定完成后：内部_client就等于外部建好的通信兵，可以直接调用通信功能

================================================================================
四、四大固定工控读写方法（代码固定，永不修改）
================================================================================

1. ReadRegister 读寄存器
   固定用途：读取设备里存放数字的寄存器数据
   可读内容：电机当前位置、目标位置、电压、电流、温度、转速
   返回值：ushort 纯数字
   调用格式：文书.ReadRegister(设备地址, 寄存器地址);
   实例：
       ushort 现在位置 = 文书.ReadRegister(1, 1009);

2. WriteRegister 写寄存器
   固定用途：往设备寄存器写入数字命令
   常用场景：设置目标位置、写入运行参数、设备启停数字指令
   调用格式：文书.WriteRegister(设备地址, 寄存器地址, 写入数字);
   规则：设备只认数字，不认 true/false；1 = 启动、2 = 停止，都是厂家设备手册规定死的
   实例：
       文书.WriteRegister(1, 1010, 1); // 1号设备 1010地址 写入1=启动

3. WriteCoil 写线圈
   用途：控制设备开关量动作（点动、正转、反转、电磁阀开关）
   传参只能用：true / false
       true  = 接通、开启、点动运行
       false = 断开、关闭、停止点动
   调用格式：文书.WriteCoil(设备地址, 线圈地址, 布尔状态);
   实例：
       文书.WriteCoil(1, 104, true); // 1号设备104线圈 正向点动开启

4. ReadDI 读离散输入（只读开关）
   用途：读取外部传感器、限位开关状态
   特点：只能读、不能写
   返回值：bool
       true  = 触发、到位、碰到限位
       false = 未触发、远离限位
   实例：
       bool 碰到正限位 = 文书.ReadDI(1, 2);

================================================================================
五、三个地址彻底分清（最易混淆知识点）
================================================================================

1. 设备地址（站号）
   出厂默认：所有设备默认地址都是 1
   单台设备直接用 1，不用修改
   多台设备必须手动修改设备本身地址（拨码开关 / 厂家参数软件）
   代码里的数字必须和设备内部设置完全一致，否则无法通信
   不属于代码自定义，是设备的硬件身份编号
   所有读写方法的第一个参数，全都是它

2. 寄存器地址
   存放数值数据的位置：位置、温度、电压等
   用const常量固定写死，防止写错
   示例：
       public const ushort ADDR_CURRENT_POSITION = 1009; // 当前位置地址

3. 线圈 / 限位地址
   线圈地址：控制动作开关
   离散输入地址：读取外部限位传感器
   同样按照设备手册填写，固定不变

================================================================================
六、常量 const 用法
================================================================================

关键词const：定义固定不变的地址编号
作用：不用记枯燥的数字，用英文名字代替，代码好读、不易出错

统一写法：
   // 位置类寄存器地址
   public const ushort ADDR_POSITION_1      = 1000;
   public const ushort ADDR_CURRENT_POSITION = 1009;
   // 控制寄存器地址
   public const ushort ADDR_CONTROL         = 1010;
   // 线圈地址
   public const ushort ADDR_COIL_MANUAL_FORWARD = 104;
   // 限位输入地址
   public const ushort ADDR_DI_POS_LIMIT     = 2;

================================================================================
七、数字命令 和 true/false 本质大区别
================================================================================

数字 1、2、3、4
   用于WriteRegister写寄存器
   是设备厂家规定的运行命令
   代表：启动、停止、调速、模式切换
   设备只认识数字

true / false
   用于WriteCoil线圈、ReadDI限位
   代表电路通断、开关状态
   属于程序逻辑判断用语，设备不识别

绝对不能混用：写启动不能传 true，控制点动不能传数字 1

================================================================================
八、方法代码通用规则
================================================================================

ReadRegister、WriteRegister、ReadCoil、WriteCoil、ReadDI
   内部实现代码全部是行业标准 Modbus 协议，一辈子固定不变，项目直接复制粘贴，无需修改一行
   CRC 校验算法：固定公式，直接自带使用，不用理解原理

所有方法只需要修改三处内容：
   1. 设备地址（1、2、3）
   2. 寄存器 / 线圈 / 限位地址
   3. 写入的命令数字或布尔状态

================================================================================
九、执行逻辑总口诀
================================================================================

新建通信兵，填好串口与波特率
传入自定义 Modbus 文书类完成绑定
常量固定所有设备内部地址
读数值用 ReadRegister，写运行命令用 WriteRegister 传数字
控制点动开关用 WriteCoil 传 true/false
读取限位传感器用 ReadDI
第一个数字永远填写设备本身设定好的站号

十、关键词极简释义汇总
================================================================================

ModbusSerialClient：现成串口通信类（负责收发数据）

ReadRegister     ：读数值寄存器方法
WriteRegister    ：写数字命令寄存器方法
WriteCoil        ：写开关线圈方法
ReadDI           ：读只读限位开关方法
slaveId          ：设备站号 = 设备地址
address          ：寄存器 / 线圈 / 限位地址
const            ：定义固定不变地址常量
构造函数         ：创建对象时自动传参绑定
线圈 Coil        ：可读写控制开关
离散输入 DI      ：只读外部传感器开关
ushort           ：寄存器专用数值类型
bool             ：开关状态专用类型
CRC 校验         ：Modbus 通信固定校验规则，保证数据无误
